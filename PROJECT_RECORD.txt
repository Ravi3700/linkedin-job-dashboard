PROJECT RECORD
===============

Project identity
----------------
LinkedIn Job Search Hub. Public India-focused job-search and career-resource hub across job families, locations, companies and platforms. Developer credit configured in the site: Ravi Kumar Shrivastav.

Current architecture
--------------------
Root index.html contains the public dashboard. CSS is split into main.css, components.css, responsive.css and the public-only redesign layer. The Jobs view renders all 444 original search shortcuts from data/site-content.json; the data is managed only through the existing GitHub pull-request admin. Career company/platform records remain in data/career-data.js. Public filters, Open All and Close Tabs operate on the rendered published sections.

Folder and responsibility map
-----------------------------
index.html: dashboard, Jobs/Career panels, static search sections, navigation and footer.
about.html: verified project/developer information only.
request-job.html + js/request.js: browser-only request builder and validation; configured request links open the existing Microsoft Forms destination.
css/: base, component and responsive styles.
data/locations.js: centralized city/state map.
data/config.js: centralized site name, Microsoft Forms destination and social URL values.
data/site-content.json: all published Jobs section content and the review-only admin write target.
data/search-data.js: legacy role and recruitment-post group definitions retained for shared helpers.
data/career-data.js: Career companies, platforms and lookup labels.
data/career-searches.js: CAREER_SEARCH_GROUPS, the 14-career-family student/fresher search expansion (same data model as search-data.js).
js/career-searches.js: renders CAREER_SEARCH_GROUPS into section markup identical to the existing city/walk-in sections and inserts it into the jobs dashboard.
js/utils.js: existing URL builders; do not change without approval.
js/filters.js: state and text visibility filtering.
js/open-all.js: category and global OPEN ALL behavior using rendered, filter-visible links.
js/tab-manager.js: generic tracking and close behavior for opened windows.
js/career.js: Career rendering, filters, tab semantics and secure rendering helpers.
js/ui.js: keyboard shortcuts and Back to Top.
js/app.js: startup initialization, filter refresh after JSON render and external-link hardening.
js/site-config.js: safely enables configured Request and social links.
js/site-content.js: validates and renders published sections from data/site-content.json.
admin/: separate existing GitHub-authenticated content-admin interface (unchanged).
worker/: optional OAuth and pull-request-only content API; credentials stay outside the repository.
manifest.json: static web app metadata.
sw.js: lightweight cache-first fallback for the static shell.
docs/: guide, architecture, security and changelog.

Feature mapping
---------------
Jobs: index.html + data/search-data.js + filters/open-all modules.
Career: index.html + data/career-data.js + js/career.js.
State/location: data/locations.js + js/filters.js.
OPEN ALL: js/open-all.js, with filtered links excluded.
CLOSE DASHBOARD TABS: js/tab-manager.js, generic for all tracked windows. Visible close controls are section-scoped and generated by js/ui.js; the header has no global Open All/Close controls.
Back to Top and keyboard search shortcuts: js/ui.js. The Back to Top control is mobile-only, appears after minimal scrolling, supports bounded pointer dragging, remembers its session position, and hides at the top.
Mobile search navigation: js/ui.js adds accessible disclosure controls to all search sections; CSS collapses them only on mobile. Collapsed anchors remain in the DOM for filtering and OPEN ALL.

Classification
--------------
Regular jobs, hiring/recruitment posts and walk-in searches remain separate sections. Do not merge them to inflate counts.

Protected data rules
--------------------
Existing search URLs are immutable. Do not regenerate, normalize, reorder, encode, decode, replace or remove them without explicit approval. New search records must preserve the existing classification and location conventions.

Security architecture
---------------------
No secrets or backend credentials are present in this repository. The admin requires external Worker secrets and GitHub approval rules; it can create a PR but cannot approve, merge or publish. See ADMIN_SETUP.md and docs/SECURITY.md.

Deployment
----------
The public pages use relative paths and no build step. GitHub Pages remains configured for the existing repository; use an HTTP server locally because the Jobs JSON is fetched at runtime. The service worker requires HTTP(S).

Microsoft Forms configuration
-------------------------
`SITE_CONFIG.requestJobSearchUrl` points to the existing Microsoft Forms destination in data/config.js. The local Request page prepares text but does not store or transmit it; navigation request links and the request-page form note link open the configured external form.

Removed features
----------------
The Job Hunt XP/streak/level game HUD and localStorage click tracking were removed because they were unrelated to the core job-search purpose.

Known limitations
-----------------
Browsers may block bulk popup opening. External career and job-platform destinations can change independently. The optional admin is not operational until the Worker credentials and GitHub review rules are configured; see ADMIN_SETUP.md.
Live duplicate-result verification is not available for LinkedIn's dynamic/search-authenticated result pages; no potentially overlapping search was removed without conclusive evidence.
Two search titles in data/career-searches.js ("BI Developer", "Business Analyst Intern") intentionally overlap with existing data/search-data.js entries; both are kept per the cross-listing policy above rather than deduplicated.
Real cross-browser manual verification of the career-search expansion has not been performed in this environment; it was instead verified with a full scripted DOM run (jsdom, served over HTTP) that loads the actual page, executes the actual scripts and checks rendered output, link counts, filtering and Open All/Close Tabs behavior. See docs/CHANGELOG.md for the fix this caught.

Maintenance procedure
---------------------
1. Read this file and docs/PROJECT_GUIDE.md before major changes.
2. Preserve existing URLs exactly.
3. Keep city/state facts in data/locations.js.
4. Keep job/post/walk-in sections separate.
5. Reuse open-all.js and tab-manager.js rather than adding category-specific window logic.
6. Update docs/CHANGELOG.md and this record after architecture changes.
7. Run JavaScript syntax checks, local-reference checks, and browser smoke tests for Jobs, Career, filters, OPEN ALL behavior, About and Request pages.
